# 技术栈详细文档 - Word 报告生成系统

本文件对系统使用的技术栈、架构决策、组件关系及未来演进进行详细说明，帮助新成员快速了解现状与设计取舍。

## 1. 总览
- 目标：提供一个清晰、可扩展的技术蓝图，覆盖后端、前端、模板生成、数据源与部署运维等方面。
- 现状重点：后端基于 FastAPI + SQLAlchemy + SQLite，前端基于 Vue 3 + Vite + Element Plus + Pinia。

## 2. 后端技术栈
- 框架/运行时：FastAPI
- ORM/数据库访问：SQLAlchemy
- 数据库：SQLite（开发与测试阶段）
- 模板生成：Word 文档模板生成（初始方案可选 python-docx / docxtpl 等）
- 依赖管理与打包：Poetry / pipenv（建议统一，便于锁定版本）
- API 风格与中间件：RESTful 风格，带有基本的输入校验与错误处理；考虑逐步引入中间件以实现日志、鉴权、限流等。
- 测试：pytest + pytest-asyncio（后续引入测试桩与覆盖率工具）

## 3. 前端技术栈
- 框架：Vue 3
- 构建工具：Vite
- UI 库：Element Plus
- 状态管理：Pinia
- 路由：Vue Router
- 组织结构：组件化、按功能区分模块，API 封装在服务层
- 测试：Vitest + Vue Test Utils（后续引入）

## 4. 数据模型与模板生成
- 数据源管理、模板管理、字段映射、文档生成、历史记录等核心域。
- 模板存储与版本控制策略、数据源的抽象、字段映射的规范化接口。
- 生成流程：数据源拉取 → 字段映射应用 → 模板填充 → Word 输出 → 版本化存档/历史记录。

## 5. 数据库设计与演进
- 当前问题：JSON 字段替代关联表，缺乏正常化关系。
- 未来方向：引入显式的关联表（如 TemplateFields、DataSourceFields、DocumentHistory 等），建立外键关系与索引。
- 迁移策略：先保留旧数据，逐步迁移到新模式，提供回滚方案与数据映射脚本。

## 6. 配置与部署
- 配置源：环境变量 + 配置文件（如 config.yaml / .env），避免硬编码路径。
- 运行环境：开发阶段使用 SQLite，生产阶段评估 PostgreSQL/MySQL 等。
- 安全性：对敏感信息进行加密存储与受控访问，后续逐步引入鉴权与权限控制。

## 7. 架构原则与模式
- 分层设计：表现层、服务层、数据访问层（Repository）分离，便于单元测试与替换实现。
- 依赖注入：尽量通过构造注入来解耦组件。对外部依赖实现接口替换。
- 可测试性：设计可测试的边界条件，尽量避免数据库直接依赖测试，使用仓储模式实现模拟。

## 8. 版本与版本管理
- 版本管理与依赖锁定： 推荐使用 Poetry 锁定依赖版本。
- 代码风格：遵循 PEP 8、MyPy 类型提示（Python 部分），以及 Vetur/TypeScript/ ESLint 的前端约束。

## 9. 未来改进方向
- 引入 CI/CD、代码静态分析、测试覆盖率可视化、性能基线与基准测试。
- 支持多模版引擎与多语言模板（扩展性设计）
- 增强监控、日志、错误聚合与告警。
